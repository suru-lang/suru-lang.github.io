rclsuru で ROS 2 のノード

rclsuru は、する で ROS 2 のノードを書くためのライブラリです。トピック・サービス・アクション・パラメータ・ログ・ROS の時刻が使え、rclcpp・rclpy のノードや ros2 の道具とそのまま話せます。このページでは、10分ほどで最初のノードを動かします。関数ごとの説明は API のドキュメント(英語)にあります。

トピックと QoSサービスアクションパラメータ/rosout へのログuse_sim_timeros2 run と launch約200のメッセージ型

01入れる

要るもの:

  • Ubuntu 24.04 の ROS 2 Jazzy(ROS 2 の手順で ros-jazzy-ros-base か ros-jazzy-desktop)
  • する 0.11.0 以上と kumu、clang(sudo apt install clang)。トップの入れ方を見てください

使う端末では毎回、作る前に source /opt/ros/jazzy/setup.bash します。rclsuru は ROS 2 のヘッダーとライブラリを /opt/ros/${ROS_DISTRO} から探します。リポジトリの docker/Dockerfile には、ROS 2・する・clang をそろえた環境もあります。

02はじめてのノード

プロジェクトを作り、rclsuru を足します。

terminal
$ source /opt/ros/jazzy/setup.bash
$ kumu 新規 hello
$ cd hello
$ kumu 追加 github.com/suru-lang/rclsuru

本体.suru を書きます。1秒ごとに chatter へ「こんにちは」を送るノードです。

本体.suru
「rclsuru」 を 読み込んで 使う

始めする とは 以下の手順です
  n とは 「hello」 を ノード作成した 結果
  p とは 文字列型 を 「chatter」 へ n で 発行者作成した 結果
  （「こんにちは」 を p へ 発行する） を 1.0 で n に 周期登録する
  「始めました」 を n で 情報記録する
  n を スピンする
  以上です

始めする

ノード作成する でノードを作り(名前は英数字と _ だけ。ROS の決まりです)、発行者作成する で発行者を作ります。周期登録する は ROS の時刻で 1.0 秒ごとに動作を行い、スピンする は Ctrl-C まで タイマーと届いたものを処理し続けます。動かして、別の端末で聞きます。

terminal
$ kumu 実行                 # 作って動かす

$ ros2 topic echo chatter std_msgs/msg/String
data: こんにちは

kumu 作る なら、ふつうの実行ファイル 出力/hello ができます。インタプリタ(suru 本体.suru)でも動きます。

03聞く

聞き手は chatter を購読し、届くたびに関数を呼びます。上の話し手や ros2 run demo_nodes_cpp talker と一緒に動かします。

listener/本体.suru
「rclsuru」 を 読み込んで 使う

始めする とは 以下の手順です
  n とは 「listener」 を ノード作成した 結果
  文字列型 を 「chatter」 から n で 聞いたこと表示すること に 購読する
  n を スピンする
  以上です

文 を 聞いたこと表示する とは （「聞きました: 」 + 文） を 表示する

始めする
terminal
$ kumu 実行
聞きました: こんにちは
聞きました: こんにちは

文字列型 は std_msgs/msg/String で、する の値は文字列そのものです。

04メッセージの型

よく使うパッケージの型を同梱しています(std_msgs・geometry_msgs・sensor_msgs・nav_msgs・example_interfaces など、全部で約200)。「rclsuru/型/パッケージ」 を読み込んで使います。次のノードは turtlesim の亀を円く走らせます。

亀/本体.suru
「rclsuru」 を 読み込んで 使う
「rclsuru/型/geometry_msgs」 を 読み込んで 使う

始めする とは 以下の手順です
  n とは 「turtle_driver」 を ノード作成した 結果
  p とは Twist型 を 「turtle1/cmd_vel」 へ n で 発行者作成した 結果
  t とは linear は （x は 2.0 の Vector3既定） で angular は （z は 1.0 の Vector3既定） の Twist既定
  （t を p へ 発行する） を 0.5 で n に 周期登録する
  n を スピンする
  以上です

始めする
terminal
$ ros2 run turtlesim turtlesim_node   # 別の端末で
$ kumu 実行

1つのメッセージから、組の型(Twist)、既定の値(Twist既定。x は 2.0 の … で一部だけ変える)、発行者と購読に渡すメッセージ型(Twist型)ができます。自分の .msg・.srv の型は 生成器.suru で作れます。

05サービス

サービスのサーバーは、要求ごとに関数を呼び、その結果を応答として返します。

足し算サーバー/本体.suru
「rclsuru」 を 読み込んで 使う
「rclsuru/型/example_interfaces」 を 読み込んで 使う

始めする とは 以下の手順です
  n とは 「add_two_ints_server」 を ノード作成した 結果
  AddTwoInts型 を 「add_two_ints」 で n に 足し算すること へ サービス作成する
  n を スピンする
  以上です

要求 を 足し算する とは （sum は （要求 の a） + （要求 の b） の AddTwoInts_Response既定） を 結果にする

始めする
terminal
$ kumu 実行 &
$ ros2 service call /add_two_ints example_interfaces/srv/AddTwoInts "{a: 2, b: 3}"

別の端末から呼ぶと sum: 5 が返ります。クライアントは クライアント作成する・サービス待機する・呼出する を使います(examples/足し算クライアント)。アクションも アクションサーバー作成する で同じように書けます(examples/フィボナッチサーバー)。

06パラメータとログ

パラメータは宣言してから使います。値は、起動時に渡された値(--ros-args -p rate:=5.0 や YAML のファイル)か、なければ既定の値です。ログは rclcpp と同じく、コンソール・/rosout・ログファイルに出ます。

本体.suru
rate とは n から 「rate」 を 1.0 で 小数パラメータ宣言した 結果
名 とは n から 「name」 を 「suru」 で 文字列パラメータ宣言した 結果
（「こんにちは、」 + 名） を n で 情報記録する

ros2 param list・get・set・dump が する のノードにもそのまま使えます。ログは 詳細記録する・情報記録する・警告記録する・エラー記録する・致命記録する の5段階です。

07ros2 run と launch

作ったノードはふつうの実行ファイルなので、ament のパッケージの lib/<パッケージ>/ に置けば ros2 run・ros2 launch で起動できます。CMake から kumu 作る を呼びます。

CMakeLists.txt
find_program(KUMU kumu REQUIRED)
add_custom_target(hello ALL
  COMMAND ${KUMU} 作る
  WORKING_DIRECTORY ${CMAKE_CURRENT_SOURCE_DIR}/hello
  VERBATIM)
install(PROGRAMS ${CMAKE_CURRENT_SOURCE_DIR}/hello/出力/hello DESTINATION lib/${PROJECT_NAME})

リポジトリの ros/rclsuru_examples が、例をこの形にしたパッケージです。

terminal
$ mkdir -p ws/src && cd ws/src && git clone https://github.com/suru-lang/rclsuru && cd ..
$ colcon build
$ source install/setup.bash
$ ros2 launch rclsuru_examples talker_listener.launch.py
