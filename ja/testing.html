入門

する の試験

する には、別の試験の道具はありません。試験は言語そのもので書きます。定義のすぐ下に短い例を、同じファイルに試験のまとまりを、大きな試験は 試験/ のフォルダに書き、1つのコマンドで全部を動かします。このページの内容は する 0.10.0 以上で使えます。文法が初めてなら、先に入門を読んでください。

例えば … は … です以下は「…」の試験です…試験するsuru --試験suruc --試験kumu 試験GitHub Actions

01試験はコードと一緒に

小さなファイル 計算.suru の例です。公開の関数が1つ、例が2つ、試験のまとまりが1つあります。特別な意味を持つ注釈はありません。例も試験もふつうの文なので、インタプリタ・コンパイラ・エディタが、ファイルのほかの部分と一緒に型を検査します。

計算.suru
# x の2倍を返します。
数 を 二倍する は 数 を 返す
x を 二倍する とは x * 2 です
例えば （2 を 二倍する） は 4 です
例えば （-3 を 二倍する） は -6 です

数 を 加一する は 数 を 返す
x を 加一する とは x + 1 です

以下は「二倍」の試験です
  （0 を 加一して 二倍する） を 2 に 一致確認する
  1 < 2 を 確認する
  以上です

加一する は 非公開とする

このファイルをプログラムとして動かすとき(suru 計算.suru)や、ほかのファイルが 「計算」 を 読み込む で読み込むときは、例と試験のまとまりを飛ばします。ビルドしたバイナリにも入りません。動くのは、試験を動かすと言ったときだけです。

02例えば で書く例

一番外に書いた 例えば 式 は 期待する値 です は、すぐ上の定義の例です。両辺が等しければ(=)合格です。終わりの です は省けます。

挨拶.suru
文字列 を 挨拶にする は 文字列 を 返す
名前 を 挨拶にする とは 「こんにちは、」 + 名前 + 「さん」 です
例えば （「太郎」 を 挨拶にする） は 「こんにちは、太郎さん」 です

例は「定義の名前の例(行)」、たとえば「挨拶にするの例(3行)」という名前で知らせます。注釈ではなく文なので、打ち間違えれば動かす前にエラーになり、気づかないうちに古くなることもありません。VS Code では、関数の名前にカーソルを乗せると、型と一緒に例が出ます。

03試験のまとまり

1行では書けない確かめは、ファイルの一番外に試験のまとまりとして書きます。以下は「二倍」の試験です の後に手順を書き、以上です で閉じます。「」の中が試験の名前です。1つのファイルに、名前の違うまとまりをいくつも書けます。

挨拶.suru
文字列 を 挨拶にする は 文字列 を 返す
名前 を 挨拶にする とは 「こんにちは、」 + 名前 + 「さん」 です

以下は「挨拶」の試験です
  文 とは 「花子」 を 挨拶にする
  文 を 「こんにちは、花子さん」 に 一致確認する
  （文 の 長さ） > 0 を 確認する
  以上です

試験のまとまりの中では、そのファイルの非公開の名前(上の 非公開とする とした 加一する など)と、「試験」ライブラリの確かめる入出力動作を、読み込まずに使えます。

確かめ意味落ちたとき
実際 を 期待 に 一致確認する2つが等しいことを確かめる等しくありません: 期待は 4 / 実際は 5
条件 を 確認する条件が 真 であることを確かめる真ではありません
理由 を 不合格にする自分で書いた理由で、すぐに落とす書いた理由

確かめが落ちると、その行と理由を標準エラーに書き、その試験を終了コード 1 で終えます。ほかの試験はそのまま動きます。

04試験を動かす

suru --試験 にファイルかフォルダ(フォルダなら中の全部の .suru)を渡すと、例・試験のまとまり・…試験する の手順をインタプリタで動かします。試験は1つずつ別のプロセスで動くので、落ちて止まるのはその試験だけです。

端末
$ suru --試験 計算.suru
✓ 計算.suru 二倍するの例(4行)
✓ 計算.suru 二倍するの例(5行)
✓ 計算.suru 二倍

合格 3・不合格 0

不合格の試験は、理由とその試験が書いたものを下に字下げして見せ、終了コードは 1 になります。2つ目の例を間違えて は 6 です と書いたときは、こうなります。

端末
$ suru --試験 計算.suru
✓ 計算.suru 二倍するの例(4行)
✗ 計算.suru 二倍するの例(5行)
    計算.suru:5: 等しくありません: 期待は 6 / 実際は -6
✓ 計算.suru 二倍

合格 2・不合格 1

道でない引数は、名前か道の一部で試験を選びます。suru --試験 計算.suru 二倍する なら 二倍する の例だけです。suruc --試験 は Go 版のコンパイラで同じことをします。ファイル1つにつき試験用のバイナリを1つ作り(ほかの -O を書かなければ -O0)、試験ごとに別のプロセスで動かします。知らせ方も同じです。

端末
$ suruc --試験 計算.suru 二倍

05試験/ のフォルダ

プロジェクト全体を、使う人と同じように使う試験は、試験/ の下のファイルに書きます。そこでは、一番外の引数のない定義のうち、名前が 試験する で終わるものが1つの試験です(ひらがなだけの名前は使えないので「二倍を試験する」ではなく 二倍試験する)。確かめる入出力動作は 「試験」 を 読み込んで 使う で、プロジェクトは 組.suru の名前で読み込みます。

試験/二倍.suru
「試験」 を 読み込んで 使う
「計算」 を 読み込む                 # 組.suru の名前で、プロジェクトを読み込む

二倍試験する は 真偽 を 返す 入出力動作
二倍試験する とは 以下の手順です
  （5 を 計算内の二倍する） を 10 に 一致確認する
  （0 を 計算内の二倍する） = 0 を 確認する
  以上です

ファイルのほかの定義(補助の関数など)は試験になりません。試験/ のファイルは、試すプロジェクトのファイルと同じ名前でもかまいません。試験/計算.suru の 「計算」 を 読み込む は自分を飛ばして、プロジェクトの 計算.suru を見つけます。kumu 新規 は試験を1つ書いた 試験/例.suru を作るので、新しいプロジェクトでもすぐに試験を動かせます。

06kumu 試験

kumu のプロジェクトでは、kumu 試験(kumu test)が全部を動かします。先にプロジェクトのソースのファイルの例と試験のまとまり、次に 試験/ の …試験する の手順です。試験のファイルは1つずつ 出力/試験/ にバイナリになり、プロジェクトの依存と C のソースとつながれて、試験ごとに別のプロセスで動きます。

端末
$ kumu 新規 計算        # 新しいプロジェクト。上の 計算.suru を 本体.suru の隣に置く
$ cd 計算
$ kumu 試験
✓ 計算.suru 二倍するの例(4行)
✓ 計算.suru 二倍するの例(5行)
✓ 計算.suru 二倍
✓ 試験/二倍.suru 二倍試験する

合格 4・不合格 0

落ちたときは、試すコードがライブラリの中にあっても、試験のファイルの確かめた行を出します。

端末
$ kumu 試験 二倍試験
✗ 試験/二倍.suru 二倍試験する
    「二倍.suru」の6行目 25文字目: 等しくありません: 期待は 11 / 実際は 10

合格 0・不合格 1

suru --試験 と同じく、kumu 試験 の後ろの言葉は、名前か道の一部で試験を選びます。読めない・型が合わないファイルは、ファイルごと不合格にして、エラーを下に出します。自分の 組.suru を持つ下のフォルダ(例/ など別のプロジェクト)は飛ばします。kumu 公開 は試験を全部動かし、不合格があればタグを付けません。

07エディタで

VS Code 拡張は、例と試験のまとまりも、ファイルのほかの部分と同じく書きながら検査します。試験/ のファイルでは、…試験する とは の行の上に「▷ 試験する」が出て、その試験だけを動かせます。プロジェクト全体は、コマンドパレットの「プロジェクトを試験する(kumu 試験)」です。

08PR ごとに動かす

kumu 試験 は不合格があれば終了コード 1 で終わるので、CI にはこれだけで足ります。次の GitHub Actions のワークフローは、push と PR のたびに kumu と clang を入れて試験を動かします。公式ライブラリも、包む C のライブラリを足して、同じ手順で試験しています。

.github/workflows/試験.yml
name: 試験
on:
  push:
    branches: [main]
  pull_request:
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: stable
      - run: sudo apt-get update && sudo apt-get install -y clang
      - run: go install github.com/suru-lang/suru/cmd/kumu@latest
      - run: ~/go/bin/kumu 試験

kumu を使わないなら、代わりに pip install suru-lang と suru --試験 . を動かします。

09次に読むもの
