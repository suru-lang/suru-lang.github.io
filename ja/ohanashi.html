おはなしの使い方

「おはなし」(ohanashi-ollama)は、手元のコンピューターで動く Ollama の LLM と、ブラウザでおしゃべりする Web アプリです。サーバーは する で書いてあり、1つの実行ファイルになります。会話は手元の SQLite にしまうので、外には出ません。

💬 会話とスレッド📒 メモ🛠 コーディングモード🧠 モデル帳📜 決まり📎 画像・PDF🌐 ウェブ💻 砂場📄 Word・PDF🐙 GitHub🔔 通知

01入れて動かす

要るものは次のとおりです。

  • Ollama と、モデルを1つ以上(ollama pull qwen3 など)
  • する 0.4.0 以降(kumu と clang)。入れ方はトップページにあります
  • libsqlite3 と OpenSSL。macOS は brew install sqlite openssl@3、Debian・Ubuntu は sudo apt install libsqlite3-dev libssl-dev
端末
# macOS で Homebrew の sqlite・OpenSSL を使うときは、先に:
$ export PKG_CONFIG_PATH="$(brew --prefix sqlite)/lib/pkgconfig:$(brew --prefix openssl@3)/lib/pkgconfig"

$ git clone https://github.com/suru-lang/ohanashi-ollama
$ cd ohanashi-ollama
$ kumu 実行

起動したら、ブラウザで http://localhost:8080/ を開きます。画面のファイルは今のフォルダの 画面/ から読むので、このフォルダで起動してください。

よく使う引数です。ほかの引数は README にあります。

引数意味既定
--ollama URLOllama の場所OLLAMA_HOST、なければ http://localhost:11434
--port ポート画面を開くポート8080
--listen アドレス待ち受けるアドレス127.0.0.1(同じ機械からだけ)
--db ファイル会話をしまう SQLite のファイルohanashi.db
--searxng URLウェブ検索に使う SearXNGSEARXNG_URL、なければ使わない
端末
$ kumu 実行 -- --port 9000 --db ~/おはなし.db
$ ./起動.sh --watch 60      # 新しいコミットが来たら作り直して動かし直す

起動.sh で動かすと、画面の ⚙ に「🔄 最新にして再起動」が出ます。--watch 秒 を付けると、その秒ごとに新しいコミットを見て、あれば git pull → kumu 作る → 動かし直す、をします。作り直しに失敗したときは、前のアプリを動かしたままにします。

02会話とスレッド

左の一覧から会話を作ったり、前の会話を開いたりします。答えは届いたところから少しずつ出て、「止める」で途中で止められます。Markdown のコードや表は整えて出し、コードは「写す」でコピーできます。

  • 会話は設定の入れ物です。モデル・指示(システムプロンプト)・温度・GitHub のリポジトリなどは会話ごとに決めます(⚙)
  • 話題ごとにスレッドを作ります。見出しの「＋ スレッド」で作ります。モデルに送るのはそのスレッドの発言だけなので、長くなっても速いままで、前の話題に引きずられません。設定は会話のものをそのまま使います
  • 「📒 メモ」で次のスレッドへ持ち越します。決めたこと(枝の名前・試験の動かし方など)を会話のメモに書くと、どのスレッドでもモデルに渡します。答えの「メモに足す」でも足せます
  • 長くなったらまとめて次へ。スレッドが長くなると「まとめて新しいスレッドへ」が出ます
  • 探す。左の「会話を探す」で、題と発言の中身からスレッドを探せます

03モードとモデル帳

見出しの「💬 会話」を押すと「🛠 コーディング」に切り替わります。コーディングにすると、コーディング向けの決まりが付き、「💻 砂場」が押されます。新しい会話は、前に選んだモードで始まります。

⚙ の「🧠 モデル帳」には、Ollama に入っているモデルの大きさ・量子化・文脈の長さ・能力(🔧 道具・👁 画像)が並びます。ウェブ検索が使えると、モデルに自分でモデルのことを調べさせて、特徴と点数(コード・会話・日本語・推論、0〜5)を記録します。新しい会話のモデルは、この点数からモードに合うものを選びます。調べた中身は「直す」で手で直せます。

04決まり

「コードを書くときの決まり」のような、モデルに守ってほしいことを「📜 決まり」として名前を付けてしまい、⚙ で会話に付けます。Claude Code の CLAUDE.md のようなものです。決まりは答えるたびに読むので、直すと付けているすべての会話に効きます。付ける場面を「いつも」「🛠 コーディングモードのとき」「💬 会話モードのとき」から選べます。

リポジトリの決まりは、リポジトリの中のファイルに書けます。「💻 砂場」か「🐙 GitHub」を使うと、作業フォルダのリポジトリで OHANASHI.md → AGENTS.md → CLAUDE.md の順に探し、最初に見つかったものをモデルに渡します。

OHANASHI.md
- 試験は `kumu 試験` で動かし、通ってから push する
- コメントと commit の文は日本語で書く

05画像と PDF を添える

ファイルを画面に落とすか、入力欄に貼るか(Ctrl+V・⌘V)、📎 で選ぶと、問いに添えられます。

  • 画像は、画像を読めるモデル(qwen2.5vl・gemma3 など。一覧で 👁 が付きます)が読みます。1つの問いに 8 枚まで
  • PDF は、ブラウザでページごとに文を取り出して、どのモデルにも読ませます。スキャンした PDF のように文字のないページは、画像にして添えられます
  • 文字のファイル(.txt・.md・.csv・コードなど)は、そのまま送ります

06ウェブで調べる

「🌐 ウェブ」を押して送ると、ウェブで調べてから答え、終わりに出典を付けます。自分で動かす SearXNG(SEARXNG_URL)か、Ollama の web 検索 API(OLLAMA_API_KEY)が要ります。調べる言葉は外に送られるので、外に出したくない問いではボタンを押さないでください。

07砂場と文書

Docker を動かしておくと「💻 砂場」を押せます。モデルが会話ごとの Docker のコンテナの中でコードを書いて動かし、結果を確かめてから答えます(道具を使えるモデルが要ります)。コンテナの /work は手元の 作業/会話の番号 なので、できたファイルを手元で開けます。はじめはネットワークにつながりません。pip などを使う会話では、⚙ の「💻 砂場からインターネットにつなぐ」に印を付けます。

文書を作れるイメージを作っておくと、「今の話を Word の報告にまとめて」「PDF にして」と頼めます。モデルが Markdown で中身を書き、砂場の中で Word か PDF にします。答えの中でできたファイルは、答えの終わりの「📄 報告.docx(24KB)」のようなリンクから落とせます。前のファイルは ⚙ の「📁 作業フォルダ」から落とせます。

端末
$ docker build -t ohanashi-sandbox 砂場    # 日本語のフォントも入ります。作ったら起動し直す
メモ: モデルが動かすコマンドは確かめずに行います。作業フォルダに大事なファイルを置かないでください。

08GitHub

GitHub の鍵(fine-grained の個人アクセストークン)を環境変数 GITHUB_TOKEN に入れて起動します。

端末
$ GITHUB_TOKEN=github_pat_… kumu 実行

⚙ の「GitHub のリポジトリ」で、会話にリポジトリを足し、それぞれ「読むだけ」か「読み書き」を選びます。「🐙 GitHub」を押して送ると、モデルがリポジトリの設定・ファイル・issue と PR を読んでから答えます。

  • 読み書きのリポジトリでは、頼めば issue を作る・直す・コメントする・閉じることができます。画面で確かめずに行い、書いたものへのリンクを答えに残します
  • 読むだけのリポジトリには書きません
  • 「🐙 GitHub」と「💻 砂場」を両方押すと、モデルがリポジトリを clone して直し、新しい枝に push して PR を作れます。git は手元で動かすので、コンテナに鍵は渡しません
頼み方のこつ: 小さいモデルは、道具を呼ばずに「push しました」と書きがちです。「github_push ツールを使って、ohanashi/fix-typo ブランチに push してください」のように道具・枝を書き、clone → 直す → push → PR を1つずつ頼み、作業ごとに新しいスレッドにすると確実です。

鍵には、使うリポジトリだけを選び、読むだけなら Contents・Issues・Pull requests を Read-only に、書くなら Issues・Contents・Pull requests を Read and write にします。

09スマホから開く・通知

ほかの機械から開くときは、Tailscale Serve を前に置くと、Tailscale につないだ機械からだけ https://機械の名前.tailnet名.ts.net/ で開けます。証明書は Tailscale が用意します。管理画面の DNS で MagicDNS と HTTPS Certificates を入れておきます。

端末
$ kumu 実行                     # --listen は既定の 127.0.0.1 のままでよい
$ tailscale serve --bg 8080     # 止めるときは tailscale serve --https=443 off

ほかのタブを見ている間に答えが終わると、タブの題の頭に「✅」(失敗は「⚠️」)が付きます。⚙ の「🔔 見ていない間に答えが終わったら通知する」に印を付けると、ブラウザの通知も出ます。押すとそのスレッドに戻ります。ブラウザの通知は localhost か https で開いたときだけ使えます。

メモ: --listen 0.0.0.0 で起動すると、同じネットワークのだれでも会話を読めます。Tailscale を使っているなら、Tailscale Serve で開くほうが安全です。

10もっと先へ

おはなしのサーバーは、する で約 4000 行です。HTTP・WebSocket・SQLite・GitHub・Ollama は、それぞれ する のライブラリにしてあるので、自分のアプリにも使えます。
